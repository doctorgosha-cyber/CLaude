# TRIALS-CLOUD-REPORT-2: 16 more tool and skill trials for NEXUS

**Session:** claude.ai cloud container, 2026-10-29. Linux x86_64, 4 vCPU, Node 22.22.0, Python 3.13.16, PHP 8.3.6, ffmpeg 6.1.1, Chromium (Playwright build 1194) pre-installed. Up to 15 trials ran concurrently, so every runtime below carries shared-CPU noise (noted per trial).

GitHub releases/API, every CDN, semgrep.dev, api.osv.dev, image hosts and all ordinary websites were refused by the egress proxy. Nothing was mocked; "not measured" is written where a measurement could not be made.
**Round-1 lessons applied:** the zip holds `checks/`, `fixtures/` (with KEY files and generators) and `runs/` (logs, commands, result.json); every skill trial ran a plain-agent pilot first and was hardened when the pilot sat at the ceiling (details per trial); every arm records tokens, tool calls and wall time; every tool records install size, runtime and Windows status.
**Method per tool:** seeded defects with KEY.json + clean controls (a finding on a control = false positive) + a baseline reproducing what NEXUS does today + the tool's defaults + one tuned config. Verdict: ADOPT = clear measured gain, low false positives, low cost; WATCH = some gain but cost/false positives/evidence not enough; REJECT otherwise.

## 1. Ajv 8 vs Frictionless for the food catalogue — ADOPT Ajv

**What ran.** 40 catalogue rows (JSON + CSV), 10 seeded faults F1..F10 (unit mismatches ×3: kJ under kcal, protein in g/kg, moisture as a fraction; impossible kcal/100 g; missing source date; duplicate id; wrong species enum; negative moisture; swapped protein/fat; stale label year), 30 clean rows plus a 40-row clean control file. Baseline = a 30-line presence-and-type validator (`runs/01-catalogue/baseline.mjs`).
**Numbers.** Baseline **1/10** (missing date only). Ajv 8.20.0 defaults (types/required/enum/format) 2/10; **tuned schema** (min/max per field, if/then on `form`, custom keywords `uniqueKey` and `proteinGteFat`) **10/10, 0 FP, 0.18 s**. Frictionless 5.21.0 defaults 2/10; tuned Table Schema + checklist 10/10, 0 FP, 0.52 s. Mechanism: ranges catch F1 F2 F3 F4 F8 F10; custom logic is needed in Ajv for F6 (duplicate id, `uniqueItems` cannot do per-key) and F9 (protein ≥ fat); Frictionless needs custom only for F9. A probe (not in the key) shows an in-range unit fault (kJ 188 on a wet row) passes both tuned validators: schemas see magnitude, not units.
**Install.** Ajv 3 s / 3.2 MB pure JS; Frictionless 18 s / 73 MB Python, `--trusted` needed for paths, validates the CSV not the JSON the calculator reads.
**Verdict: ADOPT Ajv** (`node checks/catalogue.mjs data/catalogue.json checks/configs/catalogue.schema.json`); **WATCH Frictionless** (equal recall, second toolchain, no gain for a Node team).

## 6. Image encoders — ADOPT sharp AVIF q70

**What ran.** 8 PNG sources: scikit-image sample photos (astronaut NASA PD, chelsea CC0, coffee CC0, rocket NASA PD; photo hosts are blocked here, so these stand in for product photos) plus synthetic text-on-image banners and a flat product rendering. Baseline = JPEG quality 80 via sharp (assumed hand export), 290,584 B total. Metrics: RGB SSIM (scikit-image 0.26.0) and DSSIM (`dssim` 3.5.1 built with cargo; PyPI `dssim` 1.3.0 is an unrelated package).
**Numbers.** The brief's SSIM ≥ 0.97 bar is above today's export: JPEG-80 itself scores 0.919–0.955 on 7/8 images; no WebP encoder reaches 0.97 at q90 on the text banners or 3/4 photos; AVIF reaches it at q80–90 but at 130–147 % of JPEG-80 bytes. Against the real bar "no worse than JPEG-80 on both metrics": **sharp AVIF q70 = 72 % of bytes (209 KB vs 291 KB), 8/8 under SSIM and DSSIM**; AVIF q60 = 53 % but DSSIM passes only 2/8; WebP q80 = 70 % by SSIM but DSSIM rates it below JPEG-80 on 7/8; WebP q90 = 114 % (no gain). avifenc 1.0.4 q70 = 81.5 % (sharp beats it by ~10 %); @squoosh/lib q80 AVIF = 84 %, deprecated, fails on Node 22 (`Cannot set property navigator`) unless started with `--no-experimental-global-navigator --no-experimental-fetch`. Tuned tweaks (WebP effort 6 + smartSubsample / `-sharp_yuv`): <1 % bytes. sharp's AVIF default chroma is already 4:4:4; 4:2:0 cuts bytes but drops below JPEG-80 on two photos. WebP outputs of sharp, cwebp and squoosh are byte-identical (same libwebp).
**Cost.** sharp 4 s / 30 MB, Apache-2.0 with bundled prebuilt libvips (LGPL-3.0-or-later, unmodified: fine), win32 optional deps. AVIF ~1.4 s per image at effort 4, WebP ~50 ms.
**Verdict: ADOPT sharp, AVIF quality 70 as the primary format, WebP q80 as fallback only.** `node checks/images.mjs <dir> --avif --avif-q 70 --webp-q 80 --min-ssim 0.92` converts and fails (exit 1) when any output falls under the SSIM floor; the 0.97 floor from the brief would fail 14/16 outputs including today's JPEGs.

## Skill trials (11–16): common method

Every skill trial is an A/B between a plain Claude Code subagent (arm A) and the same subagent with the skill text (arm B: SKILL.md inline for 13–16, "read `fixtures/skills/<name>.SKILL.md` first" for 11–12). Same model, same prompt otherwise, fresh copy of the fixture per run (`tools/arm-prep.mjs`), 3 reps per arm, script grading only (`fixtures/NN/grade.mjs` against hidden tests; `__grade__/` is created and removed). A plain-agent pilot ran first; where it sat at the ceiling the task was hardened (16: three rounds) or the ceiling is reported as a limit (11, 14). Per run we record tokens, tool calls and wall time (`runs/NN/usage.jsonl`), the grade (`grades.jsonl`) and the join (`summary.json` via `tools/arm-summary.mjs`). For 12 and 13 a blind pairwise design judge adds a secondary signal: full-page screenshots at 390 and 1280 px, random left/right per pair, a fixed 3-criterion rubric, one fresh judge session per pair, unblinded only after all three (`runs/NN/judge/`). Skills are pinned by SHA-256 (`fixtures/skills/SHA256SUMS`) with their licence files; `claude plugin install` was not reachable (GitHub blocked), the files came via raw.githubusercontent.com. Caveat for every skill trial: a 5-hour API rate limit interrupted some runs; those were resumed and their usage rows cover only the resumed segment (flagged per run with a `note`). Token counts include the subagent's fixed context, so only the A−B difference is meaningful.
